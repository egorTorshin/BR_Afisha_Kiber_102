# Сценарий демонстрации на 7 минут по шагам (уровни 1–3)

Демонстрация покрывает базовые сценарии уровней 1–3: поиск и модерация, веб/API-контур, свободный диалог агента, сохранение контекста, grounded-карточки и fallback.

## Шаг 1. Запуск и проверка готовности (0:00 – 0:45)

1. Запускаем контур:
   ```bash
   docker compose up -d
   ```
   *(или локально проверяем автотесты и метрики качества)*:
   ```bash
   PYTHONPATH=. python3 -m unittest discover -s tests -v
   PYTHONPATH=. python3 -m src.cli metrics
   ```
2. Показываем в консоли JSON-лог запуска со сквозным `request_id`: миграции применены, справочники городов и площадок загружены, стартовый набор из 20 событий импортирован.

## Шаг 2. Основной сценарий жителя: до карточки за 3 действия и подписка (0:45 – 2:00)

1. **Действие 1**: Пользователь отправляет боту `/start`. Бот выводит краткое приветствие с дисклеймером и компактное инлайн-меню.
2. **Действие 2**: Пользователь нажимает кнопку `🏙 Выбрать город` → `Уфа` (или отправляет текст `Что интересного в Уфе в эти выходные?`). Бот моментально возвращает подборку актуальных опубликованных событий в Уфе с кнопками карточек.
3. **Действие 3**: Пользователь нажимает на первую кнопку события (`📌 1. Балет «Журавлиная песнь»`). Открывается полная карточка события со всеми полями ТЗ: название, категория, дата и время, город и площадка, адрес, описание, стоимость, возрастное ограничение `6+`, ссылки на источник и билеты.
4. Пользователь нажимает кнопку `🔔 Подписаться: Уфа (спектакль)`, затем проверяет список своих подписок `/subscriptions` и отписывается одной командой `/unsubscribe` (запись удаляется из БД).

## Шаг 3. Многокритериальные запросы, опечатки и объяснение пустого результата (2:00 – 3:30)

1. **Запрос из раздела 2 ТЗ**:
   Отправляем в бота без возврата в меню:
   `Куда пойти в субботу с ребёнком 8 лет в Стерлитамаке, до 1000 рублей на двоих, чтобы закончилось не позже 20:00`
   Бот автоматически выделяет ограничения (`город: Стерлитамак`, `период: суббота 14.11.2026`, `окончание до 20:00`, `цена: до 500 ₽ за билет`, `возраст: до 6+`) и находит подходящий спектакль «Детская музыкальная сказка „Тайна золотой пчелы“» (12:00–13:15, 300–450 ₽, 6+).
2. **Запрос с опечаткой в названии города (Приложение А)**:
   Отправляем: `Концерт в стерлитакмае в субботу`
   Алгоритм Дамерау — Левенштейна распознаёт город `Стерлитамак` и выводит субботний концерт «Осенний дивертисмент».
3. **Запрос без подходящих данных (честный отказ и объяснение)**:
   Отправляем: `Есть ли в Салавате джаз на следующей неделе?`
   Бот не выдумывает мероприятия, сообщает, что по указанным параметрам событий не найдено, и подсказывает, какое именно ограничение можно ослабить (например, убрать уточнение «джаз» — в Салавате найдутся спектакль и выставка, либо посмотреть джаз в Уфе).

## Шаг 4. Веб-чат и агентный диалог (3:30 – 5:00)

1. Открываем `/agent` и отправляем запрос со свободными ограничениями.
2. Показываем уточняющий вопрос или результат с карточками и ссылками на события.
3. Отправляем follow-up без повторения города и даты, проверяем сохранение контекста.
4. При недоступной модели показываем честный deterministic fallback.

## Шаг 5. Сценарий модератора: импорт 100 событий, спорные карточки и отмена (5:00 – 7:00)

1. **Идемпотентный импорт файла на 100 событий**:
   Модератор загружает `data/import_100_events.csv` (через чат бота или командой `PYTHONPATH=. python3 -m src.cli import data/import_100_events.csv`).
   Бот/CLI выводит отчёт: `Всего: 100, Добавлено: 100, Отклонено: 0`.
   Повторно загружаем тот же файл — в отчёте: `Добавлено: 0, Без изменений (дубли): 100`.
2. **Очередь спорных карточек и отменённые события**:
   Выполняем `/admin_disputed` (или `python3 -m src.cli list-disputed`) — видим карточку с низкой уверенностью (`confidence = 0.65`, отсутствует ссылка на билеты).
   Проверяем отменённый спектакль 14 ноября («Ревизор»): в общей поисковой выдаче его нет, но при переходе по прямой команде `/event_11111111-1111-4111-8111-000000000008` открывается карточка с явной пометкой `⚠️ ВНИМАНИЕ: МЕРОПРИЯТИЕ ОТМЕНЕНО!`.
3. **Журнал изменений**:
   Выполняем `/admin_audit` (или `python3 -m src.cli audit-log`) — демонстрируем записи о том, кто, когда и какие изменения внёс в базу.
