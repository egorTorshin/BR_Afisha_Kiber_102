# MAX бот

MAX подключён как дополнительный транспорт существующего `BotRouter`. Он использует тот же каталог, `SearchService`, форматтер карточек, `SubscriptionService` и `AgentService`, что и Telegram. Для MAX пользовательские состояния и подписки используют ключ `max:<user_id>`, а запись `user_identities` создаётся с провайдером `max`; одинаковые числовые ID Telegram и MAX остаются разными пользователями.

## Настройка и запуск

1. Создайте чат-бота в MAX для бизнеса и скопируйте токен в `.env` как `MAX_BOT_TOKEN`.
2. Включите `MAX_BOT_ENABLED=true`. Telegram может быть включён одновременно или выключен.
3. Для production настройте HTTPS reverse proxy на `MAX_WEBHOOK_URL` с путём `/webhook`, направив его на `127.0.0.1:18081` (порт можно изменить через `MAX_WEBHOOK_PORT`). Задайте случайный `MAX_WEBHOOK_SECRET` длиной не менее 16 символов. MAX требует публичный HTTPS endpoint на порту 443 и проверяет заголовок `X-Max-Bot-Api-Secret`.
4. Выполните `docker compose up -d --build bot` (либо `docker compose up --build` для всего приложения).

Без `MAX_WEBHOOK_URL` включается официальный long polling для локальной разработки и проверки; документация MAX прямо не рекомендует его для production. В webhook-режиме сервис сам регистрирует подписку на `message_created`, `message_callback` и `bot_started` при запуске.

Пример локальной разработки: `MAX_BOT_ENABLED=true`, `MAX_BOT_TOKEN=...`, `MAX_WEBHOOK_URL=`. Локальный polling требует доступ к MAX API, токен не нужен для модульных тестов.

## Паритет и ограничения

| Функция | Telegram | MAX | Статус |
|---|---|---|---|
| Старт, меню, помощь, отмена | Да | Да | Общая маршрутизация, MAX `bot_started` и текстовые команды |
| Поиск и фильтры | Да | Да | Один `BotRouter` и `SearchService` |
| Карточки и ссылки | Да | Да | Общий форматтер; MAX поддерживает HTML и кнопки-ссылки |
| Пагинация | Да | Да | Общие callback actions и offset-фильтр |
| Подписки и отписка | Да | Да | Общий сервис, отдельная платформенная идентичность |
| Свободный текст и ИИ | Да | Да | Общий `AgentService`, отдельный principal платформы |
| Геолокация | Да | Да | MAX `request_geo_location` и location attachment |
| Админская загрузка импорта | Да | Нет | Загрузка CSV/JSON через MAX пока не подключена |
| Уведомления о новых событиях подписки | Нет | Нет | В Telegram-проекте нет доставки/планировщика; MAX это не меняет |

MAX ограничивает текст сообщения 4000 символами, callback payload — 1024, кнопки — 7 в строке и 30 строк. В MAX используется режим HTML из Bot API; callback-экран редактирует исходное сообщение через `PUT /messages`. MAX API использует корневой сертификат Russian Trusted Root CA Минцифры; файл в `src/bot/max/certs/` загружен с официального [endpoint Госуслуг](https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer), сертификат проверен по отпечатку SHA-256 `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`. Он добавляется только к TLS-контексту MAX, проверка TLS не отключается. Доставка webhook дедуплицируется в памяти процесса по ID события; после перезапуска возможна повторная обработка давно повторно доставленного события. Передачу файлов через MAX в текущем адаптере не реализовали.

## Проверка

`pytest -q tests/test_max_bot.py` проверяет преобразование клавиатур, нормализацию MAX updates и разделение одинаковых внешних ID. Проверку с реальным токеном следует выполнять только после настройки MAX-бота; успешная локальная проверка API без токена невозможна.
