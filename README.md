# Афиша культуры Башкортостана — уровни 1–3

Информационный сервис культурных мероприятий Республики Башкортостан (концерты, спектакли, выставки, фестивали, кинопоказы, экскурсии).

> **Дисклеймер:** Решение разворачивается в отдельном демонстрационном контуре и не является официальным сервисом Министерства культуры Республики Башкортостан до его штатного подключения. В действующие системы министерства изменения не вносятся.

## Текущий статус решения

Реализация подготовлена к сдаче на **Уровень 3 («Агент»)**: бот, веб/API и общий агентный контур. Итоговая оценка качества требует внешних 10 запросов и ручной проверки утверждений по разделу 9.2 ТЗ.

Состав реализованного функционала Уровня 1 (разделы 6.1, 6.2, 8, 9.1, 10 ТЗ):
- **Каталог событий в реляционной БД** (полная схема раздела 8.1 + справочники городов, площадок и категорий раздела 8.2).
- **Раздельное хранение сырых и нормализованных данных**: исходные записи сохраняются в таблице `raw_events`, что позволяет переиграть нормализацию (`reprocess-raw`) без повторного сбора.
- **Идемпотентный импорт CSV/JSON и ручной ввод**: валидация обязательных полей, пометка спорных карточек (`is_disputed`, `dispute_reason`), дедупликация по `source_hash` и `dedup_key`, детальный отчёт об импорте (добавлено, обновлено, без изменений, отклонено и почему).
- **Поддержка всех статусов событий**: `опубликовано`, `черновик`, `отменено`. Отменённые события исключены из поисковой выдачи, но остаются доступными по прямой команде/ссылке (`/event_<id>` или `/start event_<id>`) с явной пометкой об отмене.
- **Журнал изменений (`audit_log`)**: фиксация каждого действия (кто, когда и какие поля изменил).
- **Telegram-бот на русском языке**:
  - `/start` — приветствие и компактное главное меню на инлайн-кнопках;
  - поиск и фильтрация по названию, городу/населённому пункту (с исправлением опечаток по Дамерау — Левенштейну, например *«стерлитакмае» → «Стерлитамак»*), категории, дате (`сегодня`, `завтра`, `выходные`, `неделя`, `до конца месяца`, конкретная дата `ДД.ММ.ГГГГ`), цене (`бесплатно`, `до 500 ₽`, `до 1000 ₽`, `до 1500 ₽`, расчёт бюджета «на двоих/троих»), длительности и возрасту (`0+`, `6+`, `12+`, `16+`, `18+`);
  - `/start` сразу показывает меню из четырёх рядов; пресеты открывают выдачу одним нажатием, карточка доступна за **два нажатия**;
  - объяснение пустого результата с проверкой того, какое именно ограничение мешает и сколько событий найдётся при его ослаблении;
  - пагинация (кнопка «Показать ещё») и обработка свободного текста как поискового запроса без возврата в меню;
  - подписка на город и категорию и мгновенная отписка одной командой (`/unsubscribe`).

## Запуск через Docker Compose

Требуются Docker Engine с Compose и свободные порты 3000, 8000 и 5433. PostgreSQL доступен с хоста на порту 5433; внутри Compose сервисы подключаются к `db:5432`.

```bash
cp .env.example .env
docker compose up --build
```

Откройте сайт на http://localhost:3000, API на http://localhost:8000, документацию API на http://localhost:8000/docs и проверку состояния на http://localhost:8000/health. API и Next.js ждут готовности зависимостей. Браузер запрашивает API через same-origin путь `/backend`; только сервер Next.js использует `http://api:8000` внутри Compose. В клиентский JavaScript Docker hostname не попадает.

Однократный сервис `prepare` применяет миграции, загружает справочники и демонстрационные данные до запуска API и бота. При повторном запуске операции идемпотентны. Сервис `maintenance` ежедневно удаляет данные с истёкшим сроком хранения. PostgreSQL хранит данные в volume `pgdata`. Для полной очистки демо-БД выполните `docker compose down -v` (удалит данные).

Без `TELEGRAM_BOT_TOKEN` контейнер бота остаётся в standby и не мешает сайту/API. Чтобы включить его, получите токен у `@BotFather`, укажите `TELEGRAM_BOT_TOKEN=...` в `.env` и перезапустите `docker compose up -d bot`. Не добавляйте `.env` в Git. PostgreSQL и API доступны с хоста только через `127.0.0.1`; сайт публикуется на `WEB_PORT`. Для смены портов используйте `WEB_PORT`, `API_PORT`, `POSTGRES_PORT`.

В `.env.example` заданы демонстрационные пароли для запуска одной командой; перед публичным развёртыванием замените их в локальном `.env`. Отдельный `ADMIN_SECRET` не требуется: сессии используют `RATE_LIMIT_SECRET`. Если понадобится хранить хеш, вместо `ADMIN_PASSWORD` задайте `ADMIN_PASSWORD_HASH` командой `python -m src.cli hash-password`. Необязательная роль модератора настраивается через `MODERATOR_USERNAME` и `MODERATOR_PASSWORD`. Задайте `WEB_ORIGIN` равным публичному адресу сайта. Для HTTPS задайте `ADMIN_COOKIE_SECURE=true`.

Подготовка БД создаёт роли `afisha_api`, `afisha_bot` и `afisha_maintenance` с отдельными паролями из `.env`. После смены любого из них запустите `docker compose up --force-recreate prepare api bot maintenance`. Пароль владельца схемы остаётся только у `prepare`.

Импорт ограничен 2 МиБ и 2000 записями по умолчанию. Сроки хранения: подписки — 180 суток, заявки, сырой импорт и отчёты — 365 суток, журнал — 730 суток. Значения задаются переменными из `.env.example`.

## Агентный API и локальные модели

`POST /api/v1/agent/chat` принимает `{"message":"...","conversation_id":"..."}`. При первом запросе сервер создаёт диалог и HttpOnly-cookie `agent_session`; переданный клиентом `conversation_id` сам по себе не даёт доступа к чужому диалогу. Веб-чат доступен на `/agent` и встроен в главную страницу; Telegram и HTTP используют общий `AgentService`.

В базовом запуске задан `AI_MODE=no-ai`: поиск работает через детерминированный fallback и не требует моделей. Для локального режима сначала загрузите две закреплённые GGUF-модели с проверкой SHA-256, затем подключите overlay:

```bash
python scripts/setup_models.py
docker compose -f docker-compose.yml -f compose.local-ai.yml up -d --build --wait
```

Jev получает только типизированные признаки запроса без исходного текста и выбирает вычислительный маршрут LIGHT/HEAVY. Модели не подключаются к БД и могут только предложить вызов одного из шести зарегистрированных инструментов. Аргументы повторно валидируются сервером; `subscribe` и `save_feedback` требуют явного подтверждения пользователя. Карточки формируются только по идентификаторам, реально возвращённым успешными инструментами.

Контейнеры моделей не публикуют порты на хост, работают во внутренней сети с read-only filesystem, снятыми capabilities и `no-new-privileges`; веса монтируются read-only. `compose.benchmark.yml` временно публикует model endpoints только на `127.0.0.1` и не предназначен для deployment. Внешние OpenAI-совместимые endpoints можно подключить явно через `compose.native-ai.yml`; не направляйте его на недоверенный сервер, поскольку ему передаётся содержимое агентного запроса (кроме отдельного Jev-роутера, который видит только признаки).

Агент хранит максимум 20 последних реплик до `AGENT_DIALOGUE_TTL_DAYS` (по умолчанию 30 дней). Случайный session token хранится в БД только как SHA-256. Трассировки содержат очищенный от телефонов и email запрос, краткий план, инструменты и аргументы фильтрации; доступ к ним имеет только роль `admin` по `GET /api/v1/admin/agent/traces/{request_id}`.

Публичный контракт v1 включает каталог, `POST /api/v1/feedback` и подписки: `GET/POST/DELETE /api/v1/subscriptions` с `subscriber_id`, а также `DELETE /api/v1/subscriptions/{subscription_id}`. Существующий `/feedback` сохранён.

## Демонстрация за 5 минут

1. **0:00–1:00** — запустите Compose и откройте сайт; покажите главную и реальные карточки из PostgreSQL.
2. **1:00–2:00** — найдите события по городу/категории, откройте карточку и покажите фильтры каталога.
3. **2:00–3:00** — откройте `/docs`, вызовите `/health` и `/api/v1/events`.
4. **3:00–4:00** — отправьте обратную связь или покажите страницу `/feedback`.
5. **4:00–5:00** — перезапустите контейнеры; покажите, что данные сохранились и дубли не появились. При заданном токене дополнительно покажите бота.

## Модель и стоимость диалога (Раздел 10, 11, 12 ТЗ)

- Архитектура: **Jev (1.5B) → Light/Heavy (3B) → Deterministic Fallback**. Jev выбирает маршрут; Light предлагает один поиск, Heavy выполняет ограниченный план через типизированные инструменты, а резервный контур ищет без модели. Карточки формируются только из БД.
- Стоимость локального диалога по внешним токенам — **0,00 ₽**. Для API конфигурации расчёт: `Σ(входные_токены × цена_входа + выходные_токены × цена_выхода) / 1 000 000 × курс USD/RUB`. По проектной оценке при заданных ценах модели — **< 0,15 ₽** за диалог при пороге ТЗ **≤ 5 ₽**; фактическая стоимость без настроенного `AGENT_MODEL_PRICES_JSON` и курса не измеряется. `agent-metrics --rub-per-usd <курс>` выводит её при наличии цен.

## Обработка персональных данных и срок хранения подписок (Раздел 10 ТЗ)

- В таблице `subscriptions` хранятся исключительно технический идентификатор пользователя Telegram (`user_id`), выбранный город (`city`), категория (`category`), дата создания и дата истечения подписки (`expires_at`).
- Телефоны и домашние адреса не запрашиваются и не сохраняются; имя, язык, город и геолокация в опциональном профиле задаются самим пользователем и не требуются для поиска.
- В структурных JSON-логах (`src/utils/logger.py`) идентификатор пользователя односторонне хешируется (`SHA-256` с префиксом `usr_`), а любые случайные телефоны или email-адреса в тексте автоматически маскируются (`[REDACTED_PHONE]`, `[REDACTED_EMAIL]`). Каждому запросу присваивается сквозной `request_id`.
- **Срок хранения подписок**: по умолчанию **180 суток** (`SUBSCRIPTION_RETENTION_DAYS=180`), после чего запись автоматически очищается методом `cleanup_expired()`. При вызове команды `/unsubscribe` или нажатии кнопки «Отписаться» запись **немедленно и физически удаляется** из БД (`DELETE FROM subscriptions`).
- Диалоги агента удаляются по TTL вместе с серверной привязкой browser-session; диагностическая трасса хранит очищенный запрос и фильтры для проверки решений агента.

## Ограничения

1. Каталог использует подготовленный набор событий; автоматический сбор внешних афиш и геосервис в этот запуск не входят.
2. Демонстрационные пароли из `.env.example` нужно заменить перед публичным развёртыванием.
